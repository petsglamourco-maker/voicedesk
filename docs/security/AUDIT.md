# Security audit: gap list (2026-10-24)

This audit checks VoiceDesk against the product security standard: OWASP ASVS L2 (web and API), MASVS (mobile) and the OWASP Top 10 for LLM applications (AI).

The audit was read-only and covers the whole repo on branch `security/hardening`. Each item gives a severity, the file or setting involved, and the fix. Items marked **pre-launch** don't put anything at risk while VoiceDesk runs locally with demo data. They must be fixed before paying customers.

## Already solid (keep)

- **Database isolation:**
  - forced row-level security (RLS) on all 27 tenant-data tables, with a CI guard test;
  - the runtime DB role is `NOSUPERUSER NOBYPASSRLS`;
  - every `/api/tenants/*` route checks membership and permission, and returns 404 to outsiders.
- **Audit log:** append-only, enforced by a trigger and `REVOKE`. Platform (cross-tenant) access is audited.
- **Secrets:**
  - stored keys use AES-256-GCM (`SecretBox`, bound to context);
  - git history has no secrets;
  - there are no `NEXT_PUBLIC` secrets and no analytics cookies.
- **Accounts:** email verification is required; passwords are hashed with scrypt.
- **Webhooks and tokens:**
  - WhatsApp HMAC uses a constant-time compare;
  - form webhook secrets use a constant-time compare;
  - public keys and tokens are 144-bit random;
  - the OAuth `state` is signed and bound to the user.
- **AI controls:**
  - AI disclosure and the recording notice are fixed phrases;
  - the back-office assistant only proposes, and a person approves;
  - help and assistant tools are scoped to the business.
- **Dependencies:** exact pins, a frozen lockfile, and gitleaks plus `pnpm audit` in CI.

## Low

- Permissions-Policy is missing `microphone=(self)`.
- `X-Frame-Options: DENY` also applies to the widget frame.
- Better Auth cookie settings aren't made explicit.
- Some list endpoints aren't paginated (knowledge sources, feedback, platform lists).
- The help Markdown accepts `/\host` links.
- `/api/docs` is public.
- No API versioning.
- Feedback tokens never expire.
- The WhatsApp verify token uses `===`.
- Staff can hard-delete contacts.
- The widget's `localStorage` use should be documented as strictly necessary.

## Pre-launch (Phase 7), required before paying customers

These are high once hosted:

- **TLS and data at rest:** TLS and HSTS at the edge; encryption at rest (managed Postgres with point-in-time recovery, S3 with KMS); per-tenant keys for recordings.
- **Retention:** per-tenant retention and automatic deletion (recordings, transcripts, conversations, AI tool logs).
- **Data subject rights:** export and **erasure** for a person (DB, files, embeddings), plus tenant offboarding that also deletes files.
- **Privacy paperwork:** privacy notice, DPA, sub-processor list, DPIA, RoPA, transfer assessments; privacy links in the widget, forms and WhatsApp.
- **Monitoring and alerts:** Sentry (EU), central logs, alerts for failed logins, role changes, platform access, exports, spend and call volume. Twilio SMS-pumping protection.
- **Backups:** automated encrypted backups with a tested restore, and a defined recovery point and time (RPO/RTO).
- **Security docs:** SECURITY.md, `security.txt`, incident response plan (ICO within 72 hours), runbooks (key leak, account takeover, toll fraud, restore).
- **Assurance:** STRIDE threat model, external penetration test, Cyber Essentials Plus.

## Not applicable now

- **§10 Payments:** VoiceDesk takes no payments yet. Apply this section when Stripe billing is built (Phase 7).
- **§11 Mobile:** no mobile app yet. Its controls are **binding requirements for the mobile build**, recorded in SECURITY.md and CLAUDE.md:
  - tokens in Keychain or Keystore, never in plain storage;
  - certificate pinning; no secrets in the bundle; obfuscated release builds;
  - a jailbreak and root warning;
  - sensitive screens hidden in the app switcher;
  - biometric unlock;
  - push notifications with no sensitive content;
  - validated deep links.
- **Bulk exports:** none exist yet. When one is built, it needs re-authentication, an audit entry and an alert.
- **PECR marketing:** VoiceDesk sends no marketing yet; any campaign feature needs a consent check, a way to unsubscribe and TPS screening.
