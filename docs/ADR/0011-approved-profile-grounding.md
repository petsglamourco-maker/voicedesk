# ADR 0011 — The approved business profile is the agent's source of truth

- **Status:** Accepted (2026-10-17)

## Context

The brief is strict: the agent must never invent prices, policies or availability. Raw retrieval over crawled pages is noisy (stale pages, marketing copy, partial tables), and answers must be fast.

## Decision

- **Profile generation:** a structured, versioned **Business Profile** (`BusinessProfile` Zod schema, where `null` means unknown) is generated by the reasoning model from the ingested knowledge. Documents are prioritised (structured data, home, contact, hours, prices…) within a 40k-token budget and marked as untrusted data in the prompt.
- **Human approval:** a person must approve the profile before customers see it. Only the **approved** version is put into the agent's system prompt, always in full. Drafts and edits are versioned, and approval is audited.
- **Retrieval for the long tail:** `search_knowledge` covers questions the profile doesn't answer. Results are capped, labelled as reference data, and never override the profile.
- **Grounding rules in the prompt:** state business facts only from the profile or tool results; otherwise offer a callback or message. With no approved profile, the agent is told it knows nothing about the business.
- **Booking availability** comes only from the profile's hours, service durations and booking rules, plus existing bookings. It is computed in code, never by the model.

## Consequences

- Answers to common questions are fast and need no retrieval, and the prompt cache covers the profile.
- Facts change only when a person approves a new version. A weekly recrawl updates retrieval, and owners regenerate the profile when their site changes.
- The evals check for prices not present in the profile.
